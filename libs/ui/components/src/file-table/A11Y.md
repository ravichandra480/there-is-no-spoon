## Structure and semantics

- Native `<table>` with a visually hidden `<caption>` (the `label`, default "Files") and `<th scope="col">`
  headers. The selection column header has visually hidden text "Select" (no empty header cells).
- Native checkboxes: select-all exposes "mixed" through the `indeterminate` property; no ARIA state is
  hand-rolled. Row checkboxes are named "Select <file name>"; select-all is "Select all available files".
- Unavailable rows: the checkbox is `disabled` and `aria-describedby` points to "Not available for download".
- The count ("None Selected" / "Selected N") is a persistent `role="status"` region (polite), so changes are
  announced without moving focus (4.1.3).
- The status dot is `aria-hidden`; the status word carries the meaning (1.4.1).
- Column headers (`columns`) and toolbar actions (`actions`) are host-configurable. Header text names each
  column's cells; each action is a native `<button>` whose visible `label` is its accessible name (2.5.3).
  Hosts must supply meaningful, unique labels. Actions that need a selection are `disabled` while nothing
  is selected.
- The table scrolls horizontally inside a `role="region"` with `tabindex="0"`, labelled by the caption, so
  keyboard users can scroll it (axe `scrollable-region-focusable`, 2.1.1).

## Automated coverage (`file-table.spec.ts`)

- axe-core with WCAG 2.2 A/AA/AAA + best-practice tags on every state: none selected, partially selected,
  all selected, empty list, nothing selectable.
- 2.5.5 target size ≥ 44×44 on every enabled control (checkboxes are 44×44 inputs with an 18px drawn box).
- 2.4.13 focus appearance (≥ 2px, ≥ 3:1, not obscured) on select-all, a row checkbox, the download button and
  the table region.
- Keyboard: Tab order (disabled rows and the disabled button skipped), Space and Enter toggle checkboxes
  (Enter never submits an enclosing form), Enter activates Download Selected.
- Names, `role="status"`, disabled reason, `aria-hidden` dot, event payloads.
- Reflow: no toolbar overflow and a keyboard-scrollable table region at 320px.
- Token contrast: `color-success` ≥ 3:1 against `color-surface` and `color-surface-raised` in every
  theme — `ui-tokens` tests.

## Criteria that need human judgement

| Criterion                         | Assessment                                                                                                                                                                                                  |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.3.1 Info and Relationships      | Native table, caption, column headers, labelled controls.                                                                                                                                                   |
| 1.3.2 Meaningful Sequence         | DOM order = visual order: toolbar, then table rows in data order.                                                                                                                                           |
| 1.4.1 Use of Color                | Selected rows: checked checkbox + own background, distinct from hover. Available: word + dot. Forced colors: solid row outline when selected.                                                               |
| 1.4.10 Reflow                     | Toolbar wraps. The data table scrolls horizontally inside its region (data tables are exempt from the no-2D-scroll requirement).                                                                            |
| 1.4.12 Text Spacing               | No fixed heights on text; rows use `min` sizes; paths wrap with `overflow-wrap: anywhere`.                                                                                                                  |
| 2.4.6 Headings and Labels         | Labels describe purpose ("Select agent.exe", "Download Selected").                                                                                                                                          |
| 2.4.9 Link Purpose                | N/A: no links.                                                                                                                                                                                              |
| 2.4.10 Section Headings           | N/A inside the component; the host page supplies the heading. Consumers should set `label`.                                                                                                                 |
| 2.5.3 Label in Name               | "Download Selected" is visible text and the name. Checkbox names start with "Select", matching the "Select" column header.                                                                                  |
| 3.1.3 / 3.1.5 / 3.1.6             | Built-in text is short, plain English ("Selected 2", "No files"). File names and paths are data, not prose.                                                                                                 |
| 3.2.1 / 3.2.2 On Focus / On Input | Focusing or toggling never changes context; Download only emits an event the host acts on.                                                                                                                  |
| 3.3.6 Error Prevention (All)      | The component does not submit anything. The demo host shows a dialog listing the files before anything happens.                                                                                             |
| Forced colors                     | Checkbox boxes `ButtonText`, checked `Highlight`/`HighlightText`, disabled `GrayText`, focus `Highlight`. Rows: dashed `Highlight` outline on hover, solid when selected. Confirm in Windows High Contrast. |
