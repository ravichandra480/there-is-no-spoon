# Proposal

## Why

The file table's toolbar count must always match the current selection: "Selected N" for N selected files, and an explicit empty-state label when nothing is selected. The component already counts live, but the empty label reads "None selected". It should read "None Selected" to match the title-case "Selected N" and the "Download Selected" button next to it.

## What Changes

- The empty-state count text changes from "None selected" to "None Selected" (capital S). **BREAKING** for anything that matches the exact old string: host tests, e2e steps and screen-reader expectations.
- The Selection count requirement now states that N is the number of currently selected files. That count includes only files that are still present and available, and it updates after every selection change, whether the user or the host caused it. The count text is unchanged ("Selected 1", "Selected 2", …).
- The "None selected" strings in the select-all scenarios change to "None Selected".
- Out of scope: pluralisation or other wording changes to "Selected N", localisation, and how the count looks or where it sits.

## Capabilities

### New Capabilities

_None._

### Modified Capabilities

- `file-download-table`: The "Selection count" requirement changes its empty-state text to "None Selected" and states that N is derived from the current selection. The "Select-all is unchecked when nothing is selected" scenarios now expect the new text.

## Impact

- `libs/ui/components/src/file-table/file-table.ts`: the count template and the `@csspart count` JSDoc.
- `libs/ui/components/custom-elements.json`: regenerated by the `cem` target.
- `libs/ui/components/src/file-table/file-table.spec.ts`: unit tests that expect "None selected".
- `libs/ui/components/src/file-table/A11Y.md`: announcement text.
- `apps/demo-e2e/features/file-table.feature`: three steps that expect "None selected". The generated `.features-gen` files are rebuilt.
- No API, event or dependency changes.
